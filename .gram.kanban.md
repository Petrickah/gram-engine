#### Task 0.6 — Self-hosting (`cargo` module kind) + `gram add`
<!-- id: task-1789300000000-13 -->
New `lang: "cargo"` module kind delegates to real Cargo (`cargo build`/`init`/`add`) instead of reimplementing dependency management. `gram-engine` itself now builds via `gram build` (verified native + `--ci` cross-compile to Windows, running under `wine`). `gram add <dependency> [--module <name>]` creates the target module if missing, then adds the dependency for real. Fixed along the way: `gram init --git` was git-init'ing the wrong directory entirely; `cargo init` defaulted to edition 2015 (looked like a missing-dependency error); `.vscode/settings.json` now auto-generated (`rust-analyzer.linkedProjects`) so rust-analyzer isn't confused by a project root that isn't itself a Cargo project. Full writeup: `docs/wave-0-self-hosting.md`. Open question: `ModuleConfig.deps` scope (inter-module vs. external-crate) not yet decided.
Tags: `wave-0`

#### Task 0.4 — `gram build --ci`
<!-- id: task-1789300000000-4 -->
`gram build --ci` iterates every entry in a module's `targets` (currently `linux`/`windows`, via `x86_64-w64-mingw32-g++`/`rustc --target x86_64-pc-windows-gnu`) and places each binary in `../builds/<project>_<version>_<target>/<binary>` (sibling to the project dir). A plain `gram build` (no `--ci`) only ever builds for the host it's run on, ignoring the rest of `targets`. Simplified from the original `<date>-<commit>` layout — dropped since there's no actual CI pipeline consuming these artifacts yet (see CLAUDE.md's "No CI/CD until..." non-goal); revisit if/when one exists.
Tags: `wave-0`
